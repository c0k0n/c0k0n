## How I work

I care about the details that make software feel trustworthy:

- **Clarity over cleverness** — interfaces and code should explain themselves.
- **Useful over impressive** — a small tool that solves a real problem beats a large demo.
- **Evidence over hype** — document limitations, test assumptions, and let the work speak.
- **Respect for the reader** — accessible, fast, thoughtful experiences for real people.
